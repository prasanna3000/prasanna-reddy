# The Classroom

An interactive, classroom-themed study site for my M.Tech AIML courses (BITS Pilani WILP), live at
**[prasannareddy.com/classroom](https://prasannareddy.com/classroom/)**. It is part of my
[personal site](../README.md) and is linked from the homepage.

Courses so far (Semester 1):

- **AIML ZG511 · Deep Neural Networks**
- **AIML ZC418 · Introduction to Statistical Methods**

Each chapter has these tabs (a tab only appears if the chapter has content for it):

| Tab | What it is |
| --- | --- |
| **Chalkboard** | The lesson, one board at a time (← → keys work) |
| **Test-type tabs** | Optional, e.g. z-tests, t-tests, Proportions, Chi-square: the intuition for one kind of problem, its branch of the "which test?" tree, and its worked problems |
| **Worked problems** | Notebook pages where you reveal one step at a time |
| **Lab bench** | Interactive labs (e.g. step-by-step gradient descent) |
| **Flashcards** | Flip cards; mark "Got it" or "Still learning" |
| **Pop quiz** | Multiple-choice and numeric questions, graded with explanations, optionally split into sets |
| **Cheat sheet** | A printable formula sheet |

Your progress (stars, seen boards, finished problems, known cards, best quiz scores) is saved in your
browser's `localStorage` only.

Plain HTML, CSS and JavaScript with no framework and no server. Content lives in JSON files. The
layout works from 360px phones up to wide desktops.

---

## Open it

**No server needed:** open `index.html` in a browser (double-click it).

Lessons are written as `.json` in `content/`. Browsers won't let a page opened from disk read those
files directly, so they are bundled into `content/content-bundle.js`, a plain script the page loads.
**After adding or editing anything in `content/`, rebuild the bundle:**

```bash
cd classroom
python3 build-content.py
```

If you forget, the page opened from disk keeps showing the old content, or says "the board is blank"
for a new chapter. On the live site the `.json` files are read directly, with the bundle as a
fallback, but rebuild anyway so both stay in step.

## Folder layout

```
index.html                 the shell (header, footer, script tags)
build-content.py           bundles content/**/*.json into content/content-bundle.js
css/style.css              the whole classroom theme, including the phone/tablet layouts
js/core/util.js            helpers (escaping, number formatting, storage)
js/core/widgets.js         the lab/widget registry
js/core/chalkplot.js       tiny chalk-style canvas plotter
js/core/statmath.js        normal, t and chi-square pdf/cdf/inverse (for the stats labs)
js/widgets/*.js            one file per interactive lab
js/app.js                  router + every view (corridor, room, chapter tabs)
content/catalog.json       semesters → courses → chapters (the table of contents)
content/<sem>/<course>/*.json   one file per chapter or past paper
content/content-bundle.js  GENERATED by build-content.py; never edit by hand
content/_templates/chapter-template.json   copy this to start a new chapter
CLAUDE.md                  rules for AI assistants editing this folder (keep the no-server setup)
```

`content/catalog.js`, `content/_templates/chapter-template.js` and
`content/sem1/aiml-zg511/ch03-linear-regression.js` are leftovers from an older setup. Nothing loads
them, so they can be deleted. Don't create `.js` copies of content files; edit the `.json`.

## Add content

### A new chapter

1. Copy `content/_templates/chapter-template.json` to e.g. `content/sem1/aiml-zg511/ch04-classification.json` and fill it in. Leave out any section you don't need (for example no `labs`) and its tab disappears.
2. In `content/catalog.json`, point the chapter at the file and remove `"comingSoon"`:

```json
{ "id": "ch04", "number": 4, "title": "Linear Neural Networks for Classification",
  "blurb": "One neuron that answers \"which one\".",
  "file": "content/sem1/aiml-zg511/ch04-classification.json" }
```

3. Run `python3 build-content.py`, then reload the page.

### A new course

Add an object to a semester's `courses` array:

```json
{ "id": "aiml-zg512", "code": "AIML ZG512", "title": "Machine Learning",
  "room": "Room 512", "color": "#3b6fb5", "teacher": "optional",
  "description": "optional, supports **bold**",
  "chapters": [ { "id": "ch01", "number": 1, "title": "Intro", "comingSoon": true } ] }
```

`color` is the colour of the classroom door. Keep `id`s URL-safe (lowercase, dashes).

### Past papers / other groups on the board

Any chapter entry can carry `"group"` (e.g. `"Exam hall"`) and a `"label"` (e.g. `"Mid-sem · EC-2R"`) instead of a chapter number. Entries with the same group are pinned together on their own board, and `course.groupIntros` can hold a one-line note per group:

```json
{ "id": "p-ec2r-2026", "group": "Exam hall", "label": "Mid-sem · EC-2R",
  "title": "Mid-Semester, Mar 2026", "file": "content/sem1/aiml-zg511/paper-ec2r-2026.json" }
```

A paper file is an ordinary chapter file that usually has only `lesson` (one "at a glance" board) and `worked` (one problem per question).

### A new semester

Add an object to `semesters`:

```json
{ "id": "sem2", "title": "Semester 2", "subtitle": "M.Tech AIML · 2027", "courses": [] }
```

### Test-type tabs (`families`)

A chapter can carry an optional `families` array. Each entry becomes its own tab after the Chalkboard:

| Field | What it does |
| --- | --- |
| `id`, `label`, `icon` | The tab (its URL is `…/f-<id>`) |
| `title`, `lead`, `blocks` | A chalkboard with the intuition, formulas and steps (ordinary content blocks) |
| `problems` | Worked-problem title prefixes; matching problems are shown under the tab with the usual reveal-a-step behaviour |
| `treeBranch` | Optional: the start of a node label in the chapter's `tree` block (e.g. `"t-test"`); that branch is drawn at the top of the tab |

When a chapter has families, each problem matched by a family is shown **only** in that family's tab
(a problem matched by two families appears in both). The Worked problems tab then shows the chapter's
whole tree (the first `tree` block on any chalkboard), a button per family, and any problems no family
claims. Progress is shared, so a problem finished in a family tab counts on the report card.

### Content blocks (lesson boards and worked-problem statements)

| `type` | Fields |
| --- | --- |
| `p` | `text` |
| `h` | `text` (small chalk heading) |
| `list` / `steps` | `items` (bullets / numbered) |
| `formula` | `text`, optional `caption` |
| `note` | `text`, optional `label`, optional `color`: `pink` or `blue` (sticky note) |
| `trap` | `text`, optional `label` (exam-trap box) |
| `table` | `head` (array), `rows` (array of arrays) |
| `tree` | `root` (node: `label`, optional `count`, `note`, `kind` = `root`/`group`/`leaf`, `children`), optional `caption`: indented tree diagram |
| `widget` | `widget` (name), `config` (object): embeds a lab inside a board |

Inline text supports `**bold**`, `` `code` ``, `==highlight==` and `[link](https://…)`. Write maths in Unicode (ŷ, wᵀx, Σ, η, ∇, ², ₁). A single `*` is left alone, so `w*` is safe.

Quiz questions: `mcq` (`options`, `answer` = index of the right option) or `numeric` (`answer`, `tolerance`, optional `unit`). Both take `explain`. Add an optional `set` (for example `"set": "Terminology"`) to a question to group it: when a chapter has more than one set, the quiz tab shows a picker for each set and "All". Questions without a `set` go in "Chapter mix".

### Labs available

| Name | Config |
| --- | --- |
| `gd-linear` | `data` ("x1, …, xd, y" per line), `eta`, `w0` ("bias, w1, …"), `lossScale` (`"half"` default, or `"mean"`) |
| `lr-bowl` | `c`, `wstar`, `w0`, `eta`, `steps` |
| `metrics-calc` | `y`, `yhat` (comma-separated) |
| `feature-scaling` | `columns`: `[{ "name", "values" }]` |
| `perceptron` | `gate` (AND, OR, NAND, NOR, XOR, NOT), `eta`, `w` ("w0, w1, w2") |
| `softmax-calc` | `z`, `y` (sigmoid panel); `logits`, `cls` (softmax panel, 1-based class) |
| `mlp-calc` | `x`, `y`, `W1`, `b1`, `W2`, `b2` (rows separated by `;`), `hidden` (relu/sigmoid/tanh), `output` (sigmoid/softmax/identity), `lr` |
| `conv-calc` | `input`, `kernel` (rows by new line or `;`), `stride`, `padding`, `bias`, `pool` |
| `rnn-step` | `Whx`, `Whh`, `b`, `xs` (one input per `;`), optional `Who` |
| `attention-calc` | `Q`, `K`, `V` (rows by `;`), `scale` (true/false), `mask` (causal, true/false) |
| `optimizer-race` | `a`, `b` (bowl L = a·w1² + b·w2²), `w` ("4, 2"), `eta`, `beta`, `gamma`, `beta2`, `steps`, `opt` (gd/momentum/adagrad/rmsprop/adam) |
| `htest-calc` | `kind` (`mean`, `prop`, `mean2`, `prop2`, `paired`), `tail` (`right`, `left`, `two`), `alpha`, plus the inputs for that kind (`xbar, mu0, s, n, dist` · `x, n, p0` · `x1, s1, n1, x2, s2, n2, dist` · `x1, n1, x2, n2, pooled` · `pairs`) |
| `chisq-calc` | `mode` (`independence` or `gof`), `alpha`; `table` (rows by `;`) or `observed`, `expected` / `probs`, `params` |

### A new lab

Create `js/widgets/my-lab.js`:

```js
Widgets.register('my-lab', {
  mount(el, config) {
    el.innerHTML = '<div class="lab"><div class="paper lab-controls">…</div><div class="board">…</div></div>';
    // wire up events; ChalkPlot.draw(canvas, { series: [...] }) draws chalk charts
  }
});
```

Then add `<script src="js/widgets/my-lab.js"></script>` to `index.html` with the other widget lines,
**above** the `content/content-bundle.js` and `js/app.js` lines (leave those two as they are), and use
`"widget": "my-lab"` in any chapter.

Keep labs phone-friendly: wide tables already scroll inside their card on screens under 900px, but
avoid fixed pixel widths on anything else.

## Publish

The classroom is published together with the main site, from the `master` branch of
[prasanna3000/prasanna-reddy](https://github.com/prasanna3000/prasanna-reddy) via GitHub Pages
(see the [root README](../README.md)). After rebuilding the bundle, commit and push:

```bash
python3 build-content.py
git add -A
git commit -m "Classroom: add chapter 10"
git push
```

The live address is `https://prasannareddy.com/classroom/`. Routes use `#/…` hashes (e.g.
`#/sem1/aiml-zc418/ch09/worked`), so deep links work on any static host with no rewrite rules. The
`.nojekyll` file makes GitHub Pages serve files exactly as they are.
